# 会话知识助手：两步 RAG 改进

本次保留原始问答为知识来源，未实现用户知识卡片、按卡片切换聊天模型或 Agentic RAG。普通分支对话的 compact 模块未在此次修改范围内，其此前发现的问题仍待单独修复。

## 数据和索引

- 新增 0007、0008 两个迁移，仅增加派生索引、指标表和助手生成状态。原始问答及分支快照不变。旧知识索引表保留兼容，但新检索使用 `knowledge_passage` / `knowledge_passage_vector`。
- 每条完整的 user/assistant 消息按段落、句子拆分。当前每片段最多 360 字符，并保存正文偏移、消息 ID、卡片、路径、时间、对应提问。系统摘要、失败和生成中的消息不入库。问题是历史提问，不当成已证实结论。
- 分支初始快照仍引用祖先消息，不展开成重复的知识副本。
- 源消息、卡片和主题的 SQLite 触发器标记索引需要更新。未变更时跳过全量原文扫描；有变更时按指纹只替换受影响片段。指纹涵盖正文、问题背景、路径和消息版本。
- 向量分批后台更新；每会话合并并发任务，模型推理串行排队。异步返回时再次校验片段仍有效，删除或改写后的旧向量不会回写。
- 打开已有会话时后台补建索引，提问时确保关键词索引已更新。向量模型冷启动不阻塞关键词检索，冷启动期间可能漏掉仅语义相关的内容。
- 查询向量最多缓存 128 项；检索结果最多缓存 64 项、60 秒，键包含数据库、会话、关键词/向量索引版本、查询和限额。未缓存生成答案。

## 检索与回答

1. 从当前助手 thread 的近期完整问答中获取语境，最多 3 轮、约 1,200 个估算 tokens；过长的最近答案保留带提示的片段。新建问答不继承其他 thread。包含“它、刚才”等表达时，拼接近期提问帮助检索；无需额外 LLM 调用。这是规则式指代补全，不是完整的语义改写。
2. 关键词和向量检索独立召回，通过 RRF 合并排序。标题/别名提供辅助权重。概览问题补充各分支代表片段；最多 40 条最终候选。向量可用时不会因关键词结果已满而跳过语义检索。
3. 按完整片段选取证据；普通问题约 3,000、比较约 4,500、概览约 6,000 个估算 evidence tokens，且不得超过请求剩余预算。相同文本与问题背景去重；不同说法保留。同一卡片可保留多段证据，展示时共享来源编号，悬停显示本轮实际片段。
4. 请求采用保守 token 估算（原估算乘 1.35 并加消息开销），另留 15% 安全空间，以及最多 3,000 tokens 输出预算。超长问题明确报错，不能静默截掉用户问题。窗口仍取 Provider 配置，须与实际模型匹配；不是精确 tokenizer。
5. 同一会话模型流式生成，禁止外部搜索。来源不足直接返回未检索到提示，不调用回答模型。历史助手答案仅帮助理解追问，不作为新证据或再次入库。提示模型区分事实、假设与历史陈述，指出冲突。
6. 流式答案约每 250ms 保存一次，完成/停止/失败明确落盘；不完整回答不进入后续助手历史。重新订阅生成中的 run 会先返回内存中的完整进度，再接续增量；已完成 run 返回最终快照和结束事件。客户端每次主动提问携带独立幂等键，可在知识更新后重复提问。
7. 关闭助手面板不会停止后台生成，重新打开会自动连接当前问答的未完成任务；连接异常时显示错误和“重新连接”操作。后端重启时，将已开始但未完成的助手任务标记为中断并保留已落盘文字，避免永久显示生成中；尚未开始的排队任务可以继续执行。

## 观测与验证

`knowledge_rag_metrics` 每次运行保存检索耗时、首字耗时、总耗时、候选数量、来源卡片数量、输入/证据 token 估算和缓存命中。`run.usage` 保存服务商实际返回的用量；未返回时不伪造。未检索到资料而跳过模型的用量记为 0。

运行：

```sh
npm test
npx tsc -p tsconfig.server.json --noEmit
npm run build
npx tsx scripts/evaluate-rag.ts /tmp/rag-evaluation.json
# 独立 UI 测试，不使用用户数据或真实模型额度
npx tsx scripts/preview-rag.ts
```

自动测试覆盖：回答尾部事实、同卡片多段证据、语义召回不被关键词挤掉、会话隔离、来源状态筛选、修改/删除/改名后的索引和缓存、并发向量更新、指代追问、Token 预算、流式首字、中断、上游失败、重连、实际用量及无证据零调用。

2026-09-07 验证结果：10 个测试文件、84 项测试通过，服务端 TypeScript 检查和前端生产构建通过。隔离浏览器页面使用本地模拟 Provider 验证了逐字显示、连续追问、新建问答、停止后保留部分答案、刷新恢复，以及生成中关闭并重新打开助手后继续接收答案。测试未调用用户配置的真实模型，不代表真实服务商的首字延迟或回答质量已经验证。

`validation/rag-retrieval-baseline.json` 是本机合成数据基准：800 条消息、3,200 个片段，8 个位于长回答尾部的事实均进入最终证据。关闭向量推理和真实 LLM，耗时仅反映本地关键词检索、索引和组装，不是线上回答速度或整体语义准确率保证。

## 后续按测量推进

- 当前仍是本地精确向量遍历；数据规模需要时再引入近似向量索引。
- RRF 不是模型重排；学习式 reranker、复杂多主题查询拆解暂未引入，避免给每个问题增加推理延迟。
- 使用真实问答数据继续校准语义阈值（目前延用 0.3）、片段大小和证据预算；没有宣称已经通过真实模型事实准确率评估。
- 概览仅覆盖检索出的代表片段。来源可追溯不代表历史模型陈述一定正确，也不能保证整会话穷尽总结。
- `KNOW_KNOW_EMBEDDINGS=off` 仅供离线基准/受限环境禁用语义推理；普通使用不需要设置。
