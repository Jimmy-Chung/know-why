# 已知问题与限制

## 阻塞：真实联调待用户填入凭据

代码完整支持真实模型调用（联网走模型原生能力），但真实联调需用户提供有效凭据：

- **Provider API Key**（OpenAI / DeepSeek / 自定义兼容接口）：请在应用「设置」页填入。

填入后可执行的真实验证：

- T11 真实 Provider：OpenAI/DeepSeek 真实响应与流式；无效凭据/不存在模型的错误识别（已用 fake key 验证 401 鉴权错误路径）。
- T12 联网模式：关闭/自动/强制三档。
- T14 搜索异常：模型原生搜索失败、空结果等。

> 说明：开发期间已用受控 mock（OpenAI 兼容）与真实 OpenAI 端点（fake key 触发 401）验证了适配器真实 HTTP 调用与 SSE 全链路，未以演示数据冒充调用成功。

## 功能限制

- **无登录/多用户**：1.0 为个人本机版本，不含鉴权与会话隔离；多用户登录属于 1.1 规划。
- **联网范围**：1.5 起只使用模型原生联网，独立搜索（Tavily）已移除；不支持联网的模型没有联网选项。
- **自动摘要用量记录**：摘要调用的 token 用量目前记录为占位（completeChat 非流式未解析 usage 字段），主聊天流式用量按适配器返回记录。
- **停止/重试**：停止保留已生成内容并标记 `stopped`；重试基于卡片最近用户消息新建 run（幂等键不同，避免命中旧失败 run）。
- **思考参数**：发送时的思考档位随会话快照绑定；运行中改设置作用于下一次请求。不支持思考的模型会禁用下拉并提示。

## 环境限制

- **平台**：凭据首选 macOS Keychain；无 Keychain 环境自动回退到 AES-256-GCM 加密文件（绑定用户名与数据目录）。
- **Node 版本**：≥ 20。
- **编译**：`better-sqlite3` 与 `keytar` 需本机编译；缺失 Xcode Command Line Tools 时 `npm install` 可能失败。

## 待改进（非 1.0 阻塞）

- 流式 usage 解析在部分 Provider 的最终 chunk 中可能缺失。
- 知识助手检索当前依赖 FTS 重建（每次消息完成重建会话索引），超大会话下可优化为增量索引。
- 前端层叠卡片的背景层在极端深度下可能叠加超出视口；已限制最多 4 层背景。
