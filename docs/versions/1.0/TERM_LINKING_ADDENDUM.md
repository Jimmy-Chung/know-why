# Know Know 1.0 产品增补：术语全会话关联与重新探索

日期：2026-09-09  
交付对象：承接开发、联调和测试的团队  
状态：产品说明与验收设计，功能尚未实现、下列验收尚未执行。本文依据当前工程源码核对，不把历史原型能力当作现有应用能力。  
版本归属：1.0 功能增补；不改变 1.1 多用户登录规划。

## 1. 产品目标

用户在主卡片讨论到第三轮才探索“基准利率”时，第一轮、第二轮及其他分支中已经出现的同一术语，也应获得通向首次探索卡片的链接。之后新产生的相同术语继续使用这个链接。

用户可以复用已有解释，也可以通过 Shift＋点击，从术语本次出现的位置创建独立探索。会话助手读取这些探索时，应保留出处和上下文，避免把同名卡片混为一份结论。

这里的“首次定义”在产品中统一称为“首次探索”。它表示默认导航目标，不表示内容已被用户验证，也不表示它比后来的解释更正确。

### 本次交接的三项交付

1. 同一会话内，历史和新增正文中的同一术语都可点击，普通点击统一跳到首次探索卡片。
2. Shift＋悬停显示明确提示；Shift＋点击从当前出处创建新探索。
3. 会话助手区分同一术语的不同探索，正确处理重复、不同语境和互相矛盾的内容。

## 2. 范围与默认规则

- 关联范围是**当前会话的全部对话卡片**，包括主卡片和各层分支，不跨会话或 Provider 配置共享默认目标。
- 按“所有行文”的要求，本增补覆盖卡片中的用户提问和 AI 回答正文；包括段落、标题、列表、引用段落和表格单元格中的可读文本。会话助手的回答仍使用自身的证据引用交互，不额外混入本次术语链接。
- 不处理卡片标题、导航标签、输入框、用户笔记、附件内部内容、代码块、行内代码、公式、已有网页链接或来源徽章。已有链接的点击行为优先。
- 首期以**同一术语文本**匹配：统一 Unicode NFC 并去除术语首尾空白，英文按完整词匹配且忽略大小写，中文允许在句子中出现。不模糊匹配、不调用模型猜测别名。“基准利率”“联邦基金利率”等不同文本不能仅因相似就自动合并。z
- 同一术语在一条消息中出现多次时，每处都可操作；重叠术语优先匹配较长的完整术语，不生成嵌套链接。Markdown 强调等样式不能使同一句中的完整术语漏标。
- 历史重复探索均保留，不在这次功能中合并、删除或改写已有对话。暂不建设用户编辑知识卡片或知识审核流程。

## 3. 交互说明

### 3.1 首次探索与历史回填

1. 用户继续使用现有“选中文字 → 探索”操作创建第一张探索卡片。
2. 卡片成功保存后，建立“会话＋术语 → 首次探索卡片”的稳定关联。
3. 当前已显示的历史正文立即更新标记；未显示的其他卡片在打开时也应正确标记，无需用户手动刷新。早于首次探索的消息同样适用。
4. 后续新回答在生成完成后添加标记，避免流式输出中不断改变 DOM、打断选区或阅读。
5. 回填只是显示关联，不修改消息原文、消息版本、历史上下文或知识索引的正文，不生成额外模型调用。

### 3.2 普通点击

- 普通点击任意匹配位置，直接打开首次探索卡片，并同步层叠卡片、面包屑和分支树的当前节点。
- 本规则包括首次探索的源位置以及后来重新探索的源位置：**普通术语链接统一指向首次探索，不因新卡片产生而改指向最新探索**。后续探索可以通过分支树访问。
- 点击只导航，不新建锚点、卡片、消息或模型请求，不改变各卡片草稿。
- 在首次探索卡片内部点击同一术语时，保持在当前卡片，不重复加载、重置滚动或创建自引用分支。
- 首次探索仍在生成、失败或停止时，链接仍打开该卡片，使用已有生成状态和重试入口；不得把“已有卡片”等同于“已有正确解释”。

### 3.3 Shift＋悬停与点击

| 用户操作 | 界面反馈 | 结果 |
| --- | --- | --- |
| 普通悬停 | 现有术语链接样式；提示“点击查看首次探索 · Shift＋点击重新探索” | 不触发请求 |
| 按住 Shift 后移入术语 | 显示 Tooltip：“可以基于当前的卡片去创建新的上下文” | 不触发请求 |
| 指针已经在术语上，再按下 Shift | 立即切换到上述 Tooltip，可辅以轻微的探索图标或强调色 | 不触发请求 |
| Shift＋点击术语 | 该操作显示忙碌反馈，创建成功后打开新卡片 | 新建独立探索 |
| 松开 Shift、移出术语、窗口失焦 | 恢复普通提示或关闭 Tooltip | 不保留错误的 Shift 状态 |

- 点击发生时以事件中的 Shift 状态为准；不根据可能过期的 Tooltip 状态决定行为。
- “当前出处”是此次被点击术语所在的卡片、消息及精确文本位置，而非首次探索的锚点。相同消息中的不同出现位置必须可区分。
- 原有选中文字后的“引用 / 探索”入口保留。“引用”仍在当前卡片提问；“探索”与 Shift＋点击使用相同的新探索语义。
- 术语可键盘聚焦：Enter 查看首次探索，Shift＋Enter 重新探索，并提供可读的辅助说明。触屏使用已有的选词“探索”入口，不要求 Shift。
- 拖动选择文字不是点击术语，不得误触跳转或新建。复制正文仍复制原文，不带 Tooltip 文案和按钮文字。

### 3.4 新探索的上下文边界

新卡片挂在**本次被点击术语所在卡片**下面，继承其原有祖先快照，以及该卡片截至被点击消息的对话。不包含该卡片在源消息之后的讨论，不带入兄弟分支，也不自动拼入首次探索卡片的聊天内容。

本增补采用当前运行代码的消息级边界：源消息完整纳入上下文。选区偏移用于精确记录出处，不宣称现有代码已按词尾裁断源消息。实现不得顺便扩大到整个会话或修改旧快照；如未来要按选区末尾截断，需要单独设计快照兼容规则。

新探索首轮提问应表达为“请结合当前分支的上下文，解释『基准利率』的背景与含义”，不预设原解释错误。模型、联网和思考设置继续遵循现有会话配置。

新卡片有独立消息记录和后续讨论，首次探索及其内容保持不变。只新增关联元数据，不把旧卡片内容复制成新知识记录。

### 3.5 失败与重复操作

- 同一次创建请求进行中，禁止重复提交；网络重试使用相同请求标识，返回同一张卡片。请求完成后，用户再次主动 Shift＋点击可以创建另一次独立探索。
- 新卡片已落盘但首轮回答失败时，保留卡片和失败状态，重试回答而不是再建一张卡片。
- 创建失败且未生成卡片时，保留当前阅读位置并提供重试，不提前替换术语链接。
- 默认目标失效时提示“原探索卡片已不存在”，刷新关联状态并去掉失效链接，不静默跳到另一张同名卡片；已有其他探索仍可从树中访问。

## 4. 会话助手与 RAG 的产品要求

RAG 来源继续是本会话的原始问答。术语链接只表达“这些探索涉及同一词项”，不把同名卡片判定为相同内容，更不把首次探索当成标准答案。

| 检索内容 | 期望回答行为 |
| --- | --- |
| 两次探索的解释一致 | 概括一次，保留支撑结论的来源；不得把两次模型回答说成两份独立权威证明 |
| 分别解释不同场景 | 按场景说明，并引用各自卡片，例如“黄金讨论分支中强调……；债券讨论分支中强调……” |
| 两次探索存在直接矛盾 | 明确指出差异，分别引用原文；不能仅凭首次/最新、卡片标题或出现次数选定正确答案 |
| 提问明确限定某个分支 | 优先使用被指定分支的证据，不用另一个分支的同名结论替代 |
| 提问要求比较多次探索 | 在预算内召回同一术语的不同探索，避免候选全部被一张卡片占满 |
| 只检索到其中一次或证据不足 | 如实说明本次证据范围，不声称所有探索一致或已检查整个会话 |

交给模型的证据应可区分：术语标识、是否首次探索、探索卡片标识、完整分支路径、相关提问、消息时间和原文片段。回答中的引用仍能定位到具体卡片和消息。

检索排序结合提问相关性和分支语境。首次关联不带来无条件的权威加权；普通定义问题不要求读取所有同名卡片。需要比较时增加分支覆盖，但继续遵守现有候选数量及 Token 预算。

相同源消息被多个快照引用，仍只索引一次。不同探索的新回答独立索引；不能因为术语相同就丢弃整张卡片。去重不得抹掉条件、时间或否定词不同的证据。对于实质一致的片段，可以减少重复输入，但须保留可追溯出处。

矛盾提示是需要通过用例检验的模型行为，不是数据库约束，也不能保证模型必然发现所有冲突。

以下为 2026-09-09 对工作区源码的核对结果。接手团队应在实际接收的代码版本上复核，旧静态原型和压缩交接包不代表当前源码。

| 部分 | 现有实现 | 本次需要补齐 |
| --- | --- | --- |
| 正文标记 | `CardPile.tsx` 的消息视图使用该消息自身的已探索锚点，每个锚点只标记首次出现；用户提问正文没有相同的标记处理 | 基于全会话术语注册表渲染所有符合范围的出现位置；支持历史回填和跨样式文本 |
| 普通跳转 | 点击标记中的 `branch_card_id` 跳到对应卡片 | 明确区分“术语默认目标”和“当前出现位置”，普通点击统一使用默认目标 |

| 主题索引 | `knowledge_topic` 已存标题、别名和关联卡片列表 | 显式保存稳定的首次目标及重新探索关系，不能依赖标题截断、卡片列表顺序或客户端排序 |
| 上下文 | 分支通过快照引用祖先与源消息；目前实际组装使用完整源消息 | 复用消息级分叉边界，验证新探索来自当前出处；旧快照保持可读 |
| 助手检索 | 候选携带卡片/消息 ID、路径、时间、提问；两步 RAG 有预算、去重、对比覆盖及矛盾提示 | 补充术语和探索关系，针对同名卡片覆盖、出处和冲突处理增加回归用例 |

### 最低数据与接口要求

- 会话详情提供可复用的术语注册表：完整术语、规范匹配键、首次探索卡片 ID、首次源锚点 ID，以及相关探索卡片关系。术语身份不能采用最多 24 字的卡片标题。
- 链接渲染时，保留当前出现位置的消息 ID、版本和纯文本偏移；普通查看无需为每个出现位置落一条锚点记录，也无需逐词发请求。
- 重新探索入口明确表达“创建新探索”意图，携带当前出现位置和幂等请求标识；保留已有 `/explore` 调用的兼容行为。服务端校验源消息、锚点、目标及会话归属，不相信客户端传来的首次目标。
- 卡片、快照、新源锚点、探索关联和幂等结果的保存需要一致，避免重试产生重复卡片或指向未创建卡片的链接。回答生成失败独立于卡片创建结果处理。
- 术语注册表/探索关系有增量迁移和备份恢复支持。旧会话按完整源锚点文本分组，选取最早创建且仍存在的探索卡片为首次目标；时间相同时按卡片 ID 稳定排序。保留所有原卡片和源锚点，不重新运行模型。
- 关联变更应使相关客户端缓存和检索缓存失效。渲染派生标记不改变原文指纹；新增探索的实际消息仍按现有机制更新 RAG。

## 6. 验收用例

以下是待执行的验收设计，不是测试通过报告。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| T01 | 主卡片第 1、2、3 轮均有“基准利率”，第 3 轮才首次探索 | 第 1、2、3 轮所有匹配处均可点击并打开同一首次探索 |
| T02 | 首次探索前，另一个分支已有该词；首次探索后再生成新回答 | 历史分支及新增完成回答均正确关联，无需手动刷新 |
| T03 | 同一消息多次出现；术语跨粗体/普通文本；位于列表、表格、用户提问 | 每个允许位置均可操作，偏移准确；代码、公式、已有链接不被破坏 |
| T04 | 普通点击、在首次卡片内部点击 | 只导航；卡片数、消息数和模型调用数不增加；同卡片点击不重置位置 |
| T05 | 先按 Shift 再悬停；先悬停再按 Shift；释放 Shift、窗口失焦 | Tooltip 及时切换和恢复，点击行为以实际 Shift 状态为准 |
| T06 | 在另一个分支第 2 条消息 Shift＋点击，且该分支还有第 3 条消息 | 新卡片挂在该分支；包含其祖先和截至第 2 条的上下文，不包含第 3 条或其他分支 |
| T07 | 不同分支重新探索同一术语，随后普通点击任意匹配处 | 新探索互相独立；所有普通术语链接仍指向首次探索 |
| T08 | 同一消息内第二次出现该词的位置 Shift＋点击 | 新锚点准确指向第二处，不复用首次出现的位置 |
| T09 | 快速连点、请求重试、卡片创建后模型失败 | 同一请求只有一张卡片；失败状态可恢复，不改变首次目标 |
| T10 | 刷新、切换会话、恢复备份、旧会话有多个同名探索 | 默认目标稳定、关联不串会话；历史消息和原分支完整保留 |
| T11 | 拖选、复制、Enter、Shift＋Enter及触屏选词探索 | 不误跳转；复制原文；键盘与触屏替代操作可完成对应任务 |
| T12 | 助手读取含一致、不同场景、直接矛盾三组同名探索 | 分别概括、区分场景、指出矛盾，引用落到正确卡片与消息 |
| T13 | 助手只召回一个分支，或证据预算无法覆盖所有探索 | 不声称全面比较、不补造结论，输入保持在现有预算内 |
| T14 | 同一祖先消息由多张卡片继承，新探索又新增回答 | 祖先原文不重复索引；新回答正常入库；不同条件或相反结论不被去重掉 |
| T15 | 删除/失效目标或跨会话伪造来源请求 | 无死链误跳、无隐式目标替换、无跨会话引用或上下文混入 |
| T16 | 长会话、大量术语、流式回答和重复切换卡片 | 无重复包裹、嵌套链接或明显输入卡顿；普通点击无模型调用，渲染无需逐词请求 |

测试团队应使用隔离数据执行确定性的匹配、路由、上下文、幂等及索引测试；为 RAG 准备明确标注预期关系的同名卡片样本，分别检查召回证据和模型回答。模型质量评估与程序测试结果分开记录，不以提示词存在代替验证。
