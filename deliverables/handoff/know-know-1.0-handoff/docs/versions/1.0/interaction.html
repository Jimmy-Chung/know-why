Know Know 交互实现说明 1.0

版本：1.0 · 2026-09-05
供接手团队配合 产品说明书、交互原型 和 测试说明 实现与验收。

本说明提炼已确认交互与实现注意事项，不增加新功能。1.0 无登录页。原型的示例身份只表示个人空间，不应据此添加账户流程。

1. 页面与入口

区域 内容及职责
左侧 会话列表、新建会话、Provider 管理和全局默认项。
顶部 当前会话名称、绑定的 Provider / 模型、联网与思考设置、知识助手入口。
中间 当前卡片与其祖先卡片构成的层叠；只有前景卡片可编辑。
右侧 全会话分支树，纯节点与曲线，点击定位。
知识助手面板 当前会话知识的连续自然语言对话，独立保存历史，不产生树节点。

原型顶部“新会话 / 选词探索 / 多层分支 / 知识助手 / Provider”及“播放探索过程”是演示导航，不是正式产品必须保留的入口。

2. 会话与模型状态

新建会话 → 一张空主卡片 → 继承默认 Provider / 模型 → 发消息前可切换 → 开始处理首条消息后锁定 → 所有分支与知识助手沿用。

  • 全局默认项变更只影响未来新建的会话。
  • 锁定后仍可读到模型信息，禁用切换并说明原因。
  • 联网、思考设置可修改，但不能影响已经发送的运行。
  • 首条消息锁定点、本地校验失败与远端失败的区别按产品说明书中的实施建议细化，并执行 T02、T03。

3. 选中文字后的两个操作

选中当前 AI 回答文本后，在选区附近显示两个图标：引号代表“引用到当前卡片”，分支代表“探索新分支”。Hover 与键盘聚焦可获知含义，Escape 收起浮层。浮层须保持选区稳定，不能因点击图标而丢失选文。

操作 状态变化 应保留的内容
引用 当前输入框出现可移除引用块，等待用户主动发送；不新增卡片。 输入草稿、原文、来源卡片、消息及选区。
移除引用 只清除待发送引用，不清空问题文本。 当前输入草稿。
发送引用追问 当前卡片新增一条带引用的用户消息。 可回溯的来源关系，树节点数量不变。
探索 创建子卡片，带入选文与上下文，开始解释；新卡片到最上层。 父卡片记录、草稿和阅读位置，分叉快照。

普通点击已关联分支的原文选区可跳转；重新选取该文字仍能引用或探索。重复术语和多次探索须保留具体来源，不凭文字相同覆盖已有分支。

4. 卡片层叠与切换

  • 正在阅读和输入的最上层卡片始终保持水平、清晰，旋转角度为 0°。
  • 下面一层逆时针约 4.5°，再下一层约 9°，依此类推；越靠后越模糊、淡化。
  • 背景展示完整卡片轮廓及内容，不仅是标题条；不接收输入或遮挡前景交互。
  • 切换节点时，目标卡片到前景，其祖先构成后方层叠；兄弟分支留在树中。
  • 深层分支可以限制实际绘制的背景层数，但不可删数据、限制树深或持续缩小前景文字。
  • 切换时恢复该卡片的草稿、引用和阅读位置，不触发隐式模型请求。

动画时长、背景最大绘制层数等由接手团队确定；以阅读清晰、选区稳定和导航流畅为准。提供减少动态效果的适配，保持等价操作。

5. 分支树

默认仅显示圆形节点及父子曲线，不常驻显示节点标题、数量或图例。原型采用主节点在下方的布局；沿用已确认方向。

当前节点及其祖先路径突出显示。Hover 显示目标卡片标题，点击直接跳转；键盘聚焦提供相同信息，触屏可直接点击。树只承担导航，不引入拖拽重排、分支合并或编辑图关系的操作。

树节点点击恢复卡片阅读位置；来源引用点击定位具体消息或选区。两种跳转目的不同，不应都强制滚动到最后一条消息。

6. 知识助手

打开助手 → 继续既有助手对话或提问 → 在当前会话所有分支内查找 → 回答并附真实来源 → 点击来源回到具体卡片和消息。

关闭再打开应保留历史。助手使用会话绑定模型，可连续追问，不提供另一套模型选择器。默认不联网，不把模型自身知识说成已保存的内容；找不到时明确说明。面板布局和动效参照原型，数据与回答逻辑必须重新实现。

7. 正式实现需补齐的状态

以下内容按已确认功能及产品文档中的可用性建议实现；原型未覆盖的状态不得用示例文本代替。

场景 用户应看到什么
空会话、无可用 Provider 清晰的输入或配置入口，不伪造连接状态。
模型生成中 增量内容、真实运行状态和停止入口。
鉴权失败、模型失效、网络错误 可辨原因及重试入口，保留草稿和已生成片段。
搜索执行 实际搜索状态、当前服务及来源；只有确实读取正文时才显示读取网页。
强制搜索失败 明确失败，允许重试或用户主动改为不联网，不静默给出已核实式回答。
不支持思考或搜索能力 禁用对应能力并解释，不能仅凭通用兼容协议显示支持。
自动摘要 提示压缩状态与涉及范围，可查看摘要及完整原文。
摘要失败 保留原文和草稿，提示重试，不提交超限请求。
停止、刷新或重启 恢复已保存内容，区分完成、中止与失败。
删除与恢复 删除范围明确，其他会话不受影响；回收区是待团队细化的实施建议。

独立搜索配置、摘要详情及部分失败状态只有功能规则，尚无逐页视觉稿。接手团队需延续现有 UI 完成这些状态；如涉及新的重要交互取舍，提交产品负责人确认。

8. 交互验收检查

重点执行 T01–T10、T15–T20；检查前景水平、选区双操作、纯树 Hover、跨分支跳转、模型锁定、助手持续对话以及草稿恢复。验证中文输入、重复词、跨行选区、窗口变窄和键盘操作。对尚未覆盖的交互补充用例并同步文档。
