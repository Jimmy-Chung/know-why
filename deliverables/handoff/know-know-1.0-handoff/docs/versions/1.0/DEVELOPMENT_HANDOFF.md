## 3. 1.0 范围与不可改变的产品规则

1. **个人本机版，无登录。** 通过浏览器访问本地服务，不要求用户每次会话选择工程目录；不包含注册、登录、多用户或云同步。多用户登录归属 1.1。
2. **会话管理。** 可新建、切换、重命名和删除；每个会话初始只有一张主卡片。
3. **引用与探索是两种操作。** 选中 AI 回答里的文本，浮层呈现两个图标；引用留在当前卡片，探索创建独立子卡片。
4. **分支具有来源和背景。** 保存原文选区及来源消息，继承分叉时上下文；后来的父消息和兄弟分支不得自动进入子分支。
5. **前景卡片水平。** 当前卡片清晰、水平；背景卡片逐层逆时针约 4–5° 旋转并模糊。中间展示当前祖先路径。
6. **右侧是纯节点树。** 默认只显示节点与连线，Hover 才显示标题，点击跳到卡片；键盘聚焦提供等价信息。
7. **一个会话固定一个 Provider 和模型。** 新建继承全局默认，首条消息前可切换，开始聊天后锁定；主卡片、全部分支和知识助手一致。联网与思考设置仍可调整，影响后续请求。
8. **真实联网。** 首版必须提供独立搜索服务，供无原生搜索能力的兼容模型使用；搜索资料交回当前会话模型回答。不能只添加提示词或显示动画来代替搜索。
9. **知识助手是持续自然语言对话。** 在当前会话全部分支中检索、比较和总结，保留追问历史，回答可定位到原消息；不是搜索弹框，也不新增探索树节点。
10. **持久保存及自动摘要。** 刷新和服务重启后恢复内容；接近上下文上限时自动摘要并提示，可回看完整原文。

1.0 不包含跨会话全局知识库界面、附件导入、多媒体、分支合并、团队协作或收费订阅。不可把“为了未来扩展”作为提前实现登录模块的理由。

## 5. 技术方案的约束与可调整部分

建议组合为 React + TypeScript + Vite、Node.js 本地服务、SQLite、SSE、SVG 树及 CSS 卡片动画。依赖版本、具体路由层、数据库驱动、测试框架由接手团队选定并锁定；允许提出等效替代，记录理由并保证需求与可维护性。

以下结果必须得到保证：

- 消息、卡片、选区、引用、快照、运行、来源、助手历史和配置建立稳定 ID 关系，不能只保存拼接后的聊天文本。
- 分叉快照可重建，Markdown 渲染后的选区能映射到稳定来源；中文、重复词和跨行选取都要验证。
- 普通卡片只读取该路径的上下文；知识助手可查整个当前会话，但检索必须在数据层限定会话 ID。
- API Key 由本地服务管理，不进入浏览器持久存储、前端包、日志或业务数据导出。macOS 系统凭据存储为建议方案。
- 本地服务只监听回环地址，并校验请求来源与本地访问授权；这属于本地服务保护，不是用户登录模块。
- Provider 与搜索服务分开适配。模型、思考、原生搜索和工具调用的支持情况按实际接口验证，不能假定所有“兼容接口”能力相同。
- 自动模式允许模型选择是否搜索；强制模式由执行链路保证实际检索。资料不足和调用失败要如实呈现；不伪造来源或隐式换模型。
- 自动摘要使用会话模型，保留原文与摘要来源范围、版本和用量；不跨分支混入资料。预算必须包括指令、资料及输出空间。
- 运行中保存请求配置快照和明确状态。刷新、取消、断流、重启及重试不能产生假完成或重复用户消息。

技术文档中的 API 能力资料是方案编写时的参考。接手团队实施时应重新核对官方文档并用实际账户验证，特别是原生搜索、推理参数、模型上下文额度和收费行为。

## 7. 测试与验收须知

测试团队以 [测试说明 1.0](./TEST_SPEC.md) 的 T01–T21 为基线，结合正式实现补充自动化用例、边界数据和回归覆盖。该说明不是现成测试代码或已执行报告。

最低真实联调证据包括：

1. OpenAI 与 DeepSeek 各完成真实问答，锁定和能力映射正确。
2. 至少一个没有原生搜索能力的兼容模型通过独立搜索获得资料、回答并提供可追溯引用。
3. 搜索关闭、自动、强制及失败分支与实际调用记录一致。
4. 知识助手连续追问有真实会话来源，不跨会话召回。
5. 长上下文触发真实摘要，提示和原文回溯正确；模拟测试覆盖预算和失败路径。
6. 刷新、服务重启、停止、重试和备份恢复的结果符合说明。

每项结果标明构建版本、环境、验证类别、实际结果、证据、时间与缺陷编号。凭据或网络不足标为阻塞，不能算通过；原型检查、模拟集成与真实联调分开报告。不得用模型“回答看起来正确”代替请求上下文和来源数据的检查。
