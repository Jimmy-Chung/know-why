1. 产品目标与使用方式

Know Know 是以知识探索分支组织对话的 AI 应用。用户可以持续推进一个问题，也可以从回答中选取不熟悉的术语，沿着独立的分支深入了解，再随时返回原来的讨论。

已确认的首版使用方式：个人本机使用，通过浏览器访问本地服务。 用户无需为每次会话创建工程目录。1.0 不包含登录、注册或多用户模块，也不引入云同步。多用户登录明确安排在 1.1。

本机保存与离线推理是两回事：会话记录由本机应用保存，调用外部模型及联网搜索仍需要网络，并会将本次请求需要的内容发送给对应服务商。

2. 核心概念

概念 定义
会话 一次完整探索的容器，包含主卡片、全部分支、统一模型配置和知识助手对话。
卡片 一条可以持续问答的对话分支。新会话最初只有一张主卡片。
探索分支 从某张卡片的一段回答中产生的新卡片，保存父卡片、来源消息、选区及上下文快照。
引用 附着在当前卡片下一条用户消息上的原文片段，不创建分支。
知识条目 某个主题及其关联分支的索引记录。相同主题可关联多条探索，不能只凭同名自动合并。
会话知识助手 跨当前会话全部卡片查找、比较和整理已有知识的独立自然语言对话。
Provider 用户配置的模型服务连接，例如 OpenAI、DeepSeek 或自定义兼容接口。

数据关系为一棵树：主卡片没有父节点，其他卡片各有一个父节点。知识条目的关联不改变这棵树，不产生循环或分支合并。

4. 会话与模型生命周期

4.1 创建会话

  1. 左侧点击「新建会话」。
  2. 生成一张空的主卡片，带入全局默认 Provider 及其默认模型。
  3. 第一条消息发送前，可以切换 Provider 和模型。
  4. 第一条消息开始处理后，锁定整个会话的 Provider 和模型。
  5. 主卡片、所有探索分支和会话知识助手始终使用这个会话的模型。

实施建议： 以首条消息通过本地校验并持久化、进入处理队列为锁定点。空消息或尚未通过本地校验的输入不触发锁定。后续远端请求失败不自动解除锁定。若用户先给知识助手发消息，同样触发会话锁定。

4.2 配置变化

  • 修改全局默认 Provider，只影响以后创建的会话。
  • 锁定后仍显示模型名称，并说明已锁定，不呈现可切换的下拉控件。
  • 联网、思考设置可以随时修改，仅影响之后发送的请求。
  • 历史回答保留生成时的模型、能力设置和实际工具调用记录。
  • 实施建议： 修改 Provider 的模型或接口地址不悄悄改写已锁定会话的绑定；同一连接的密钥可以更新。已被历史会话使用的 Provider 优先停用而非级联删除记录。

4.3 删除与恢复

已确认支持删除会话。实施建议： 删除前明确其包含的分支和知识助手记录，先移入可恢复的本地回收区；永久清理由单独操作触发。删除不应导致其他会话的数据丢失。

5. 选区的两种操作

5.1 浮层

在当前卡片的 AI 回答中选中任意术语或一段文本，选区附近出现两个 icon：

图标 Hover 说明 点击结果
引号 引用到当前卡片 将选区作为引用带入当前卡片输入框，保持在本卡片。
分支 探索新分支 创建子卡片，带入选区及上下文，开始解释。

浮层不能替换或清空用户已有的输入草稿。点击其他区域或按 Escape 可收起。键盘聚焦应能获知图标含义；触屏上图标可直接操作，不依赖 Hover。

5.2 当前卡片内引用

  1. 点击引号图标后，在输入框上方显示引用内容。
  2. 引用块可以移除；移除只取消引用，不清空问题草稿。
  3. 用户补充问题后主动发送，不因为点击引用而自动调用模型。
  4. 发送后的用户消息同时展示引用原文和所提问题。
  5. 保存来源卡片、来源消息及选区，后续仍可定位。
  6. 引用不会增加树节点。

5.3 新建探索分支

  1. 保存父卡片 ID、来源消息 ID、选中文字及选区位置。
  2. 建立独立的子卡片和分叉时的上下文快照。
  3. 使用当前会话的模型和能力设置，针对选中内容发起解释。
  4. 保留父卡片的对话、草稿和阅读位置。
  5. 新卡片可以继续追问，也可以产生下一层分支。
  6. 原回答中的对应选区成为可点击入口；普通点击跳转，重新选取文本仍能引用或探索。

上下文实施建议： 快照包含沿祖先路径截至分叉边界的消息，以及源回答至选区末尾的内容。保留完整源回答用于回溯，但不把分叉后新增的父卡片消息或无关兄弟分支自动加入子卡片。遇到过长上下文，需要摘要策略，见技术决策。

已确认的长上下文策略： 接近模型上下文上限时，自动摘要较早内容，并在界面提示已压缩的范围。完整原文仍保存在本机，用户可查看摘要并跳回对应原文。摘要用于组织后续请求，不替换或删除历史消息。用户已接受摘要可能带来的额外模型调用成本及细节遗漏。

重复探索实施建议： 已有同一来源的分支时，允许打开已有卡片，或者明确创建另一条探索；不能悄悄覆盖已有分支。相同名称并不代表上下文或讨论目的相同。

6. 已确定的 UI 与导航

6.1 整体布局

  • 左侧：会话列表、Provider 管理与默认项。
  • 会话顶部：会话名称、会话模型、联网和思考设置、会话知识助手入口。
  • 中间：当前探索路径上的层叠卡片。
  • 右侧：当前会话的纯图形分支树。

6.2 层叠卡片

最上面正在阅读和输入的卡片始终保持水平、清晰。以它为基准，下面一层逆时针旋转约 4.5°，再下一层约 9°，依此类推，并逐层模糊、淡化。底层仍呈现完整卡片轮廓及内容，不缩成标题条。

切换目标卡片后，目标卡片成为水平的前景卡片，它的祖先路径形成下方卡片。其他兄弟分支仍留在分支树中，不全部堆在中间。

实施建议： 深层探索时仅绘制有限数量的背景卡片，用模糊轮廓表达更早层级；数据层不限制为该显示数量。前景文字不应因堆叠越来越小。动画和层数阈值由实现与阅读测试确定。

6.3 分支树

  • 默认只显示节点和曲线连线，不常驻显示节点标题、卡片数量或说明文字。
  • 主线起点及父子关系按树表达，布局方向沿用已确认原型。
  • 当前节点与到主线的路径高亮；其他节点弱化。
  • Hover 节点显示卡片标题；点击节点直接跳转。
  • 键盘聚焦提供同等信息，触屏仍能点击跳转。
  • 恢复目标卡片的历史消息、草稿和阅读位置。

7. Provider、联网和思考能力

7.1 Provider 管理

支持多个命名配置：服务类型、API 地址、API Key、默认模型、是否全局默认。正式版提供实际连接测试，区分鉴权失败、接口不可达、模型不可用和能力不支持。

首版接入 OpenAI、DeepSeek，并为自定义兼容接口提供适配入口。「兼容聊天接口」不等于具备相同的联网、推理、工具调用或来源返回能力，界面依据实际能力显示选项。

7.2 联网设置

模式 预期行为
关闭 不发起新的网页检索；可以使用当前分支已经保存的资料。
自动 允许模型按问题需要调用实际可用的搜索能力。
强制搜索 本轮必须实际尝试网页检索，再基于结果回答；不能只给模型添加一句联网提示词。

展示真实执行状态，如正在搜索、读取来源、整理回答，并保存来源 URL、标题、检索时间及引用定位。已有资料与本轮新检索结果要可区分。

搜索不可用或失败时明确提示；不能静默把未联网回答标成已核实。强制搜索失败后，由用户选择重试或改为不联网继续。

已确认： 首版增加独立搜索服务，为更多没有原生搜索能力的兼容模型提供联网资料。搜索连接单独配置，不改变会话已锁定的 Provider 和模型；搜索服务的账户、凭据与聊天 Provider 分开管理。

实施建议： 独立搜索作为通用接入路径，原生搜索作为提供商支持时的可选路径。配置中明确当前搜索来源；未配置、鉴权失败或不可达时，不能显示为可用。切换搜索来源只影响后续请求，历史记录保留当时使用的服务。具体搜索服务由开发方评估中文检索、正文获取、成本与网络可达性后推荐；真实联调前在本机配置凭据。详见技术决策 D02。

7.3 思考设置

按会话选定模型提供实际支持的推理模式或强度。支持与联网同时使用。能力不支持时禁用对应选项并说明原因。

展示真实处理状态，以及服务商允许提供的推理摘要；不伪造内部思考过程，不用动画或提示词冒充原生推理能力。

8. 会话知识助手

这是独立的持续对话面板，不是搜索结果弹框，不作为新的探索节点加入树。

  • 与当前会话使用同一 Provider 和模型。
  • 检索当前会话的主卡片和全部分支，可回顾概念、比较内容、整理探索结果。
  • 支持连续追问，保存自己的对话历史，关闭后重新打开可以继续。
  • 回答必须依据已保存的消息和资料，附卡片与消息来源。
  • 点击来源定位到原卡片中的对应消息或选区。
  • 未找到时明确说未检索到，不能把模型自身知识描述成用户已保存的内容。
  • 默认不对外搜索，不把助手生成的总结反过来当作一手知识来源反复索引。

示例：“我们刚才探索过哪些概念？”→“赛博朋克和《阿基拉》有什么关系？”→点击来源返回卡片。

9. 本地保存与异常处理

正式版必须保存会话、卡片树、消息、引用、分叉快照、知识索引、助手对话、来源、配置及草稿。刷新或重启本地服务后应能够恢复。

实施建议：

  • 用户消息先保存再调用模型；流式回答以可恢复的部分状态落盘，完成后标记完成。
  • 停止生成保留已有内容并标明中止；失败显示原因，支持原请求重试。
  • 分支初始请求失败时保留卡片与来源，不产生“看起来成功”的假回答。
  • 调用中的设置采用发送时快照，不受用户随后修改设置影响。
  • 备份包括业务数据，不把明文密钥夹带到导出文件。
  • 密钥由本地服务安全保存，不存入前端代码或普通日志。

10. 1.0 验收场景

下表为验收目标，执行步骤与结果记录规范见 测试说明 1.0。当前未执行正式应用测试。

编号 验收条件
A01 新会话带入默认模型，首条消息前可切换，开始聊天后全部卡片和知识助手均锁定到同一模型。
A02 在“赛博朋克是一类科幻表达”中选取“赛博朋克”，出现引用与探索两个 icon。
A03 点击引用、填写问题并发送，原卡片新增带引用的消息，分支数量不变；移除引用不丢草稿。
A04 点击探索产生子卡片，记录正确的来源选区和快照；继续探索产生孙卡片。
A05 父卡片后续追加内容不会改变已创建分支的初始背景；兄弟分支不串上下文。
A06 最上层始终水平，背景逆时针层叠并模糊；输入、选词和跳转均可正常操作。
A07 树中默认没有标题文字，Hover 可查看，点击可返回目标卡片及来源位置。
A08 至少完成 OpenAI 和 DeepSeek 各一次真实对话测试；配置界面不能以演示数据冒充连接成功。
A09 对支持联网的已配置模型，完成真实搜索并返回可打开的来源；关闭模式不会新增搜索调用。
A10 不支持联网、鉴权失败或搜索失败时有清晰反馈，强制搜索不会静默退化。
A11 思考设置确实映射为所选模型支持的参数，历史消息保留发送时设置。
A12 知识助手可跨同一会话分支查找、连续追问并跳到来源，不召回其他会话的内容。
A13 刷新浏览器和重启服务后，可恢复消息、树、引用、助手历史与配置；重试不产生重复用户消息。
A14 至少一个没有原生搜索能力的兼容模型，通过独立搜索获取真实资料并回答；搜索前后会话模型不变，引用可追溯。
A15 长上下文触发自动摘要后有明确提示，可查看摘要及对应原文；历史消息和分支锚点完整保留，后续请求不超出模型预算。

真实 Provider 验收需要用户在本机配置可用密钥和模型。文档完整、接口模拟通过或 UI 可以点击，都不等于以上真实联调完成。
